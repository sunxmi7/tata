# 运营数据分工：友盟 / 自建埋点与统计 / 做不了

来源：漏洞跟踪「后台 · 运营需求」整理。日期：2026-11-27。  
只谈**数据从哪来、谁出数**；活动/弹窗的配置页仍是自建后台，不列入本表。

## 1. 友盟做更合适

行为与增长分析，接 SDK + 隐私披露第三方统计即可，不必自建分析引擎。

| 需求 | 备注 |
|---|---|
| 用户每日活跃（DAU） | 启动/会话 |
| iOS / Android 新增、激活 | 与「注册日新增」口径可能不同，看数时要区分 |
| 注册渠道（抖音 / 小红书 / 应用商店等） | 靠渠道包或下载配置 |
| 次日留存、留存趋势与对比 | |
| 首页入口点击 | 自定义事件 |
| 探索入口点击 | 自定义事件 |
| 活动入口曝光与点击 | 自定义事件 |
| 各入口点击率与排名 | |
| 各入口页面跳出率 | |
| 弹窗曝光与点击 | 只出数；弹窗内容配置仍在塔塔后台 |

## 2. 我们后端做埋点与统计

### 2.1 业务库统计（一般不用客户端行为埋点）

| 需求 | 数据来源 |
|---|---|
| 每日新增用户、新增趋势 | `app_users.created_at` |
| 用户画像（性别 / 年龄） | 现有用户资料；已有统计接口可增强 |
| 注册地区分布 | **注册时记 IP，异步回填省/市**；解析失败归「未知」 |
| 累计收入（日 / 周 / 月 / 套餐） | IAP 验单成功订单（可补金额快照） |
| 付费人数、付费率 | 成功订单去重用户 / 约定分母 |
| 付费订单明细与导出 | `iap_orders` 等 |
| 用户列表、搜索、详情、权益/邀请/消费流水、导出 | 账号与业务表 |
| 「功能使用」查询 | **仅业务单据**（占卜、追问等），不是全量点击轨迹 |

### 2.2 若有必须进自有库的埋点

下列情况才自建 `analytics` 上报（与友盟二选一做主分析，避免两套正式口径）：

- 事件要和 `user_id` / `reading_id` / 订单强绑定，且运营要在塔塔后台下钻到人  
- 法务要求行为数据只存在自有服务器  

默认：**增长看板以友盟为准；账号与钱以自建为准。**

## 3. 做不了（不当正式能力）

| 项 | 原因 |
|---|---|
| 硬广告 ROI（花费 → 注册 / 付费） | 要广告平台或专业归因，不是基础友盟 + IP |
| 街道级定位 | IP 只有省/市量级，且有 VPN / 运营商偏差 |
| 未接 SDK、未改隐私时的真·日活 / 留存 / 点击 | 不能服务端编造 |
| 个人全量「每一屏点击回放」 | 隐私与成本；最多查业务单据 |
| 用友盟收入当唯一财务真相 | 钱以自建验单为准 |
| 无渠道参数却断言来自某投放平台 | 猜不出来 |

---

## 4. 一句话

- **活、留、点、渠道包** → 友盟  
- **注册、地区（IP）、画像、用户与付费** → 我们后端统计  
- **硬归因、精确定位、没上报就假装有行为数据** → 不做
