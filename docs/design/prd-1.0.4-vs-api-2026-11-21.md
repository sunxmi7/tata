## 4. PRD 自己不一致（落地前要产品点头）

1. **会员额度不够时推不推 3 张牌。**  
   §20.4 情况二：额度少就优先匹配能付得起的、甚至 ≤3 张白名单。  
   §6.4 / §20.4.5 / §26：池子 >0 但不够完整任务，**不得**改用赠送/邀请，也不得为省额度推不相关牌。  
   建议按后写的 6.4 + 26：能力匹配优先，不够就提示买补充包。

2. **扣费时机。**  
   §21 路径 A 是确认后先扣再抽；路径 B 是抽完再付。现网更像路径 B。要按身份拆两条，不要合成一次扣。

3. **附录 B 写 V2.6，正文有 V2.7 第 26 章。** 会员池合并以第 26 章为准。

4. **邀请码 = 账号 ID。** 现网对外是 6 位 `public_id`。若改成数字 `user.id`，必须保证和兑换码格式不撞。

## 5. 建议落地顺序

只排「已确认会改代码」的，待配置数字不插队。

1. **权益账本重做：** 去掉每日免费；注册赠送独立批次；邀请按笔、双方各 3、一年有效；会员池分套餐/补充包，到期失效。  
2. **扣费顺序与受理节点：** 统一优先级；有权益先扣再抽，无权益抽后付费；免费用户禁追问。  
3. **邀请 + 兑换一个 API；下线账号合并。**  
4. **问题检测本地化 + 牌阵本地推荐配置。** 映射没 `frozen`、04/05/17/18 没验收，正式环境不自动推荐那几套。  
5. **灵数 78 映射与补抽。**  
6. **年运售卖通路**（价未锁只改规则不改死价格）。探索牌阵库跟产品配置走。

接口路径能复用的继续复用（`/quota`、`/redeem`、`/readings/*`、`/yearly-reports/*`）。新规则优先改账本和结算，少开新 path。
