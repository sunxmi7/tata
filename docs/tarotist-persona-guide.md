# 塔罗师人设撰写说明

> 对象：运营自填 / 本地种子。人设落在 `tarotists` 表，**不是** Grok Bot Skill。  
> 解牌时后端会拼：共用解牌规则 + `name` + `persona` + `voice` + `banned` + `ask_style`。

## 字段怎么用

| 字段 | 给谁看 | 写什么 | 长度建议 |
|---|---|---|---|
| `name` | 用户 + 模型 | 塔罗师名字 | 短 |
| `display_copy` | 用户列表/卡片 | 一句话气质标签 | ≤12 字 |
| `blurb` | 用户简介 | 1～2 句介绍 | ≤60 字 |
| `tags` | 用户标签 | JSON 字符串数组，2～3 个 | 每项 ≤6 字 |
| `avatar_url` | 用户头像 | URL；空则客户端占位 | — |
| `persona` | **模型主指令** | 身份、立场、结构、样例 | 300～800 字 |
| `voice` | 模型 | 语速、语气、用词习惯 | 1～3 句 |
| `banned` | 模型硬约束 | 绝对不能说/做的 | 分号或顿号列举 |
| `ask_style` | 模型 | 追问怎么问 | 1～2 句 |
| `enabled` | 运营 | 是否上架 | — |

`persona` 是主体；`voice` / `banned` / `ask_style` 是硬约束，不要和 `persona` 互相矛盾。

## `persona` 必写 6 块

用小标题或短段落写清楚（模型读得懂即可，不必 markdown 华丽）：

1. **身份**：谁、和用户的关系（如温和陪伴者 / 结构梳理者）。
2. **语气**：句长、是否比喻、是否调侃、严肃时怎么切换。
3. **解读立场**：先情绪还是先结构；建议偏行动还是偏留白；不改牌义。
4. **结构**：一次回复的默认顺序（例如：接情绪 → 逐牌 → 总评 → 一个小建议）。
5. **禁区摘要**：与 `banned` 对齐的人话版，可稍展开。
6. **样例**：各给一段「好回答要点」和「反例（不要这样）」。

## 验收清单（改完自测）

- [ ] 同一问题问 4 个师，语气能明显区分
- [ ] 没有「你一定会…」「活该」等 `banned` 内容
- [ ] 悲伤/危机场景：照野会收起调侃；知晚不会鸡汤空转
- [ ] 追问符合各自 `ask_style`（隐川只补一个缺口；明序先确认问题）
- [ ] 牌义不被人设带偏（人设只影响表达，不改牌）

## 本地怎么改

1. 管理端 http://127.0.0.1:5666 → 塔罗师，或直接改库。
2. 改库示例：

```sql
UPDATE tarotists
SET persona = $1, voice = $2, banned = $3, ask_style = $4,
    display_copy = $5, blurb = $6, tags = $7
WHERE name = $8;
```

3. 种子（`server/internal/tata/store.go`）只在**首次插入**时生效；已有行不会被 seed 覆盖。本地补齐用 UPDATE；要进仓库就同步改 seed 文案 + 提 PR。

## 首版四人定位（勿串味）

| 名字 | 用户侧一句话 | 模型侧核心 |
|---|---|---|
| 知晚 | 温和、慢一点 | 先接情绪，再讲牌；可指出问题但不羞辱 |
| 明序 | 清楚、有步骤 | 先结构后解释；接情绪但不拖 |
| 隐川 | 短、留白 | 话少；先答原问题再补牌面 |
| 照野 | 直，但不伤人 | 轻度犀利；调侃可关；危机时收声 |

共用解牌底线（代码已注入，人设里不要反着写）：先按牌面/牌位/正逆位解释，再按人设说话；**不得改牌**。
